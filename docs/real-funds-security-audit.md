# HoneBill real-funds security audit

**Decision — Block.** Keep real deposits, withdrawals, and offline settlement disabled until the applicable P0 items are closed. The current mobile signer can approve a backend-prepared contract call without checking that it matches the user's intent. The checked-in production mobile profile and active ramp implementation use Testnet, and the offline contract can settle an old voucher against a changed recipient mapping.

**Reviewed on** 23 November 2026 (Singapore). **Source revision** `0d09ba32e7b527105ba50d469e4aa3cb2103ef69`. The untracked `security-auditor` skill was present when the review started. The target is a future production release holding real funds. Findings describe the source at this revision. Production exposure, deployed WASM, effective configuration, balances, provider controls, and operating procedures were unavailable for verification.

| Priority | Meaning |
| --- | --- |
| **P0** | Launch gate. Resolve or exclude the affected capability through an independently verified release configuration. Core signer and release identity gates apply to every funded launch. |
| **P1** | High-priority security work. Resolve confirmed High findings before the affected capability handles real funds. Close evidence gaps that could change the launch decision. |
| **P2** | Defense in depth. Track the fix and its acceptance criterion with an owner. |

Severity estimates the consequence under the stated prerequisites. Priority determines when to act. Confirmed findings have high confidence in the cited source behavior unless otherwise noted. Production exposure is unverified for every finding. Evidence gaps carry a priority without an assigned vulnerability severity.

**Patch routing.** The last column names the lead layer, the starting files and the agent skills for each item. Mobile frontend means the Expo app in `apps/mobile`. Deployment, custody, and provider work goes to the relevant operational owner. Use `$security-auditor` to review completed fixes. Patch the active code paths linked below.

## Local verification and limits

- **63 backend tests passed across eight suites** using local fixtures and mocks. Coverage included voucher encoding, reconciliation helper, JWT TTL, lock behavior, SMS security utilities, wallet history, settlement service and QStash processing. These tests verify local behavior only.
- **Soroban suite did not run.** The offline Cargo run lacked a cached dependency. A clean-cache retry could not reach the public registry. The Rust findings are based on source and existing test review.
- A filename-and-line-only pattern scan of tracked text looked for Stellar seed, PEM private key and AWS access key shapes. It returned one candidate in a historical test fixture. Validity and use were unverified. The scan did not cover Git history, untracked files, built artifacts or other secret types. No secret values were recorded.
- Production services, deployment dashboards, provider accounts, credentials, balances and customer records were outside the available evidence. Current dependency advisories were not measured. The review did not send SMS, broadcast transactions or modify application code.
